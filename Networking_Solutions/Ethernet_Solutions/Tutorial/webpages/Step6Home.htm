About this board

This page comes from a PIC18F67J60 on an Olimex PIC-WEB board. The PIC has its own Ethernet controller, so there is no network chip on the board: the PIC itself sends every byte of this page.

The page is not a file. It is a table in program memory, the same memory as the program. The HTML2GCB converter made the table from Step6Home.htm when the program was compiled.

Why this page is long

One table must fit in one block of the PIC's program memory. So the converter starts a new table when the next line would take the table past 2024 bytes. It cuts only between lines, never inside a line.

This page is longer than 2024 bytes, so the converter made two tables: Step6Home1 and Step6Home2, and two sizes: Step6Home_Size1 and Step6Home_Size2. The program must read both, or the page stops in the middle.

If you can read the last line of this page, both tables were sent.

How to keep a page small

  • Use short names for CSS classes and JavaScript functions.
  • Draw repeated rows with a JavaScript loop, not as many copies of the same HTML.
  • Do not send the whole page again to update the numbers. Send a small JSON answer instead (the /v address).
  • Every byte of the page uses program memory, and sending 2000 bytes takes about half a second.

The rules for values

  • One value on each line: var, a name that ends in _GCB_BYTE, an equals sign, a number and a semicolon.
  • No other line may have both an equals sign and a value name.
  • A value is one byte: 0 to 255. For a bigger number use two values and add them in the page.
  • For text use one value per letter (its character code) and join them with String.fromCharCode.

Where the values come from

The first value of the page is the potentiometer on AN8, read with ReadAD when the request arrives. The second value is the red LED on RB4: 1 when it is on. The Toggle link asks for /t0, and the program switches the LED in HTTP_Action.
